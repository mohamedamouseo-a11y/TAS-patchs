Root cause of previous fail-closed stop:
The official script `scripts/deploy-active-release.sh` defines:
ROOT="${APP_DEPLOY_ROOT:-/var/www/automotivecrm}"
APP_NAME="${PM2_APP_NAME:-automotivecrm}"
TRUST_ROOT="${DEPLOY_TRUST_ROOT:-$ROOT/.atomic-release/trust/v3.6}"

The previous invocation reached the script without APP_DEPLOY_ROOT, causing the legacy default `/var/www/automotivecrm` to be used and the deployment to stop on `/var/www/automotivecrm/current must be a symlink`.

Required correction:
1. Do not modify the deploy script.
2. Before deployment, inspect the exact invocation boundary (local shell / SSH / sudo) and ensure APP_DEPLOY_ROOT, PM2_APP_NAME, and DEPLOY_TRUST_ROOT are injected into the SAME final process that launches `bash .../deploy-active-release.sh`.
3. Do not rely on a parent-shell export if an SSH or sudo boundary may discard environment variables.
4. If sudo/root privilege is required, inject the variables after the privilege boundary, e.g. with `sudo env ... bash ...`, or an equivalent documented mechanism that demonstrably reaches the final bash process.
5. Before the real deploy, run a non-mutating environment-boundary probe on the deployment host that prints only these sanitized values from the same privilege/SSH boundary:
   APP_DEPLOY_ROOT
   PM2_APP_NAME
   DEPLOY_TRUST_ROOT
