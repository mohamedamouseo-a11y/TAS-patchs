TAS Vehicle Brand Central V1

Purpose
- Add Vehicle Brands as central TAS master data managed from Admin Settings.
- Require an active central brand for file-based Excel imports.
- Store brandId on Excel import batches and a normalized lead-to-brand interest relation.
- Allow Automotive Catalog records to use central brandId while preserving the legacy brand text as a compatibility mirror.

Production-safety design
- Additive database objects only. No DROP, DELETE, TRUNCATE, reset, destructive migration, or column rename.
- No change to drizzle/schema.ts, so the trusted release schema manifest remains unchanged.
- No foreign keys in V1, reducing DDL lock and rollback coupling. Application-level validation enforces active brand IDs.
- Existing automotive_vehicles.brand text is preserved. Existing rows may keep brandId=NULL until intentionally edited/migrated.
- Existing historical Excel batches remain valid with brandId=NULL. New file imports are required to provide brandId.
- Duplicate Excel leads are NOT silently mutated with a new brand; only newly created leads receive the Excel brand interest record.
- The patch builder refuses to operate unless production server/routers.ts already imports tasExcelCompetitiveQueueSafe, preventing regression of Excel Import V1 error sanitization.
- Inactive brands remain historically addressable but are hidden from new Excel selections.
