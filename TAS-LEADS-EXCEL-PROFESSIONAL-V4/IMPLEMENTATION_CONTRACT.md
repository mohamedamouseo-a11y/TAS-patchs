## 2. Correctness invariants

These are non-negotiable:

1. `Lead Overview` contains exactly one row per exported lead ID.
2. No lead is duplicated because it has multiple notes, activities, deals, transfers, assignments, or reminders.
3. Every non-deleted Sales Note for every exported lead appears exactly once in `Sales Notes`.
4. Every non-deleted Activity for every exported lead appears exactly once in `Activity Timeline`.
5. Every applicable Deal for every exported lead appears exactly once in `Deals`.
6. Every Transfer History record for every exported lead appears exactly once in `Transfer History`.
7. Every applicable Follow-up/Reminder record appears exactly once in `Follow-ups`.
8. Child sheets are linked by stable `Lead ID` and their own stable record ID.
9. Export count is independent from the currently visible/paginated Leads table page.
10. No silent truncation is allowed.

Use stable primary-key deduplication as a final defensive step even if SQL is already one-row-per-record.

## 3. Date-range semantics

The current UI requires an export date range. Preserve that UX unless there is a strong existing architectural reason not to.

Professional semantics for V4:

- The date range and active Leads filters determine the **lead selection set**.
- After those leads are selected, export the **complete history** for those selected leads.
- Do not apply the lead-selection date range to `internal_notes`, activities, deals, transfers, or follow-ups merely because those child rows are older than the selected lead range.

This is intentional: the workbook is a complete exported Lead Profile package, not an event-period report.

The Summary sheet must state this clearly:

`Lead selection range: <from> — <to>; related history: complete for selected leads.`

## 4. Row-limit behavior

Current behavior defaults to 100 and caps at 5000. Replace this behavior.

Required behavior:

- Default action exports **all matching leads** for the chosen filters/date range.
- Do not send the current table page size as export limit.
- Remove the misleading concept that `5000` equals “All”.
- A safety ceiling may remain to protect memory/server health, but it must be explicit and must never truncate silently.
- If matching lead count exceeds the safety ceiling, return an HTTP error such as 422/413 with a human-readable message containing both the match count and configured ceiling.
- The UI must show that error instead of downloading a partial workbook.

Prefer a configurable ceiling rather than an unexplained magic number. Do not introduce a new infrastructure dependency solely for this patch.

## 6. Data-loading architecture

Do not produce the workbook from one giant SQL query joining all one-to-many tables.

Required architecture:

1. Query the unique lead selection set once.
2. Normalize/deduplicate selected Lead IDs.
3. Load each child collection independently for those IDs.
4. Build maps for lead display metadata.
5. Deduplicate every child collection by its own primary key.
6. Sort deterministically.
7. Render each collection to its own sheet.

For large `IN (...)` lists, use safe batching/chunking if required by the database/driver. Do not construct unsafe raw SQL strings from user input.

## 7. Formatting / professional quality

Use existing `exceljs` dependency.

All sheets must have:

- readable professional title/header styling consistent across sheets
- frozen header row (or appropriate Summary layout)
- AutoFilter on tabular sheets
- sensible widths
- wrapped long-text columns (notes/descriptions)
- top vertical alignment for long-text rows
- consistent `dd/MM/yyyy` and `dd/MM/yyyy hh:mm AM/PM` formatting or equivalent existing project convention
- stable sheet ordering

Also:

- Phone cells must be written as text.
- User-controlled textual values beginning with `=`, `+`, `-`, or `@` must be neutralized against spreadsheet formula injection (for example prefix with an apostrophe while preserving visible content as reasonably as Excel allows).
- Strip HTML from rich text while preserving paragraph/line breaks.
- Normalize invalid/null values to blank cells rather than `undefined`, `[object Object]`, or invalid dates.
- Workbook must open cleanly in Excel/LibreOffice/Google Sheets without repair warnings.
